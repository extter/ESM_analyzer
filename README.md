#### Dimensionality Reduction (PCA)
To reduce the anisotropy of the protein embedding space , we implemented a scalable dimensionality reduction pipeline:

- **Feature Extraction**: Residue-level embeddings are extracted from the 28th layer of ESM-2, yielding a 1280-dimensional latent space for each amino acid

- **Incremental PCA (IPCA)**: Given the massive scale of the dataset (millions of residues), we utilized an incremental approach (batch_size = 64)

- **Projection**: The original 1280-dimensional space is projected onto the top 640 principal components

The PCA was fitted on a balanced dataset (UniRef, TonB variants, and random sequences) to ensure the components capture both natural evolutionary signals and structural deviations

***

### `segment_pooling/`

**Mean pooling** was discarded because it collapses embeddings into a **narrow cone** in embedding space.

Instead, this module implements **segment-based pooling**:

1. Embed residues individually.
2. Divide embeddings into **segments** (possibly by domains).
3. Apply **mean pooling** within segments.
4. **Normalize** segment embeddings.
5. Compute sequence similarity as the **mean cosine similarity** of corresponding segments.

####  Files

- `test.py` — Checks environment setup and verifies segment pooling functionality.
- `segment_number_selection.py` — Evaluates distances between conservative and non-conservative mutations for various segment counts.

>  **Tradeoff:**
> - Fewer segments → more averaging, less local detail.
> - More segments → higher resolution, more noise.

## `markov/` — Evolution Simulation in PCA-Transformed Embedding Space

This module implements a Monte Carlo Markov Chain (MCMC) simulation that performs sequence evolution **directly in the PCA-transformed ESM-2 embedding space**.

The workflow is divided into two stages:

1. `chain_cycle.py` — standard MCMC evolution  
2. `chain_ultra_optimized.py` — second-stage refinement (run only after the first script)

---

# Stage 1 — `chain_cycle.py`

## Overview

This script performs stochastic protein evolution toward a fixed target (TonB) by maximizing **cosine similarity in embedding space**.

The simulation operates in:

- **Model:** `esm2_t33_650M_UR50D`
- **Layer used:** 28  
- **Original embedding dimension:** 1280  
- **PCA projection:** 640 principal components  
- **Segment-based pooling:** 24 segments  
- **Similarity metric:** cosine similarity in pooled PCA space  

The PCA model must already be fitted and stored at:
../pca/joblibs/Total_ipca_fitted.joblib


---

## Embedding Pipeline

For each sequence:

1. Forward pass through ESM-2 (layer 28).
2. Remove CLS/EOS tokens.
3. Apply PCA transformation on GPU:
   \[
   X_{PCA} = (X - \mu) W^T
   \]
4. Divide the sequence into 24 equal-length segments.
5. Perform mean pooling inside each segment.
6. Flatten the pooled matrix into a vector of size:
   \[
   24 \times 640
   \]

All operations (ESM forward, PCA projection, and pooling) are executed on GPU.

---

## Mutation Model

Each MCMC step generates:

- `K_PROPOSALS = 8` candidate sequences

Mutation types:

| Type | Probability |
|------|------------|
| Substitution | 98% |
| Insertion | 1% |
| Deletion | 1% |

### Substitutions

- Scored using **BLOSUM62**
- Boltzmann-weighted sampling
- Temperature: `T = 1.7`
- Self-mutations are explicitly excluded

This produces biologically plausible mutations while maintaining sufficient exploration.

---

## Selection Strategy

For each step:

1. Compute cosine similarity of all 8 candidates.
2. Rank them.
3. Keep the top `TOP_M = 4`.
4. If any candidate improves similarity → choose randomly among improving ones.
5. Otherwise → choose randomly among the top 4.

This hybrid strategy balances exploitation and controlled exploration.

---

## Acceptance Rule (Metropolis Criterion)

Let:

\[
\Delta = \text{sim}_{next} - \text{sim}_{current}
\]

- If Δ ≥ 0 → always accept  
- If Δ < 0 → accept with probability:

\[
P = e^{\beta \Delta}
\]

Default: beta_orig = 800


### Plateau Escape Mechanism

If the mean similarity increase over the last: lookback = 80 steps

is ≤ 0 (chain stagnation), then: beta = beta_orig / 8


This reduces selection pressure and enables escape from local minima.

---

## Simulation Parameters

| Parameter | Value |
|------------|--------|
| Steps | 7500 |
| Segment count | 24 |
| PCA components | 640 |
| Save threshold | 0.90 cosine |

Convergence typically occurs between 4000–5000 steps.

# Stage 2 — `chain_ultra_optimized.py`

## Overview

This script performs a **second-stage fine-tuning** starting from the best sequences obtained with `chain_cycle.py`.

While Stage 1 performs global exploration from random sequences, this stage operates in a **high-similarity regime (>0.98)** and focuses on ultra-precise optimization toward the TonB target.

The workflow is:

1. Parse all `markov/runs/` folders.
2. Extract the best high-similarity sequences from each run.
3. Use them as **seeds** for a high-pressure refinement MCMC.
4. Push similarity beyond **0.99+** using adaptive temperature and increasing selection pressure.

---

## Automatic Seed Extraction

Before fine-tuning, the script scans: ./runs/

For files: sequences_over_<threshold>_<timestamp>.txt


For each run:

- Extract sequences with `cosine_to_tonb > 0.98`
- Keep only the top sequence per run
- Remove duplicates
- Save everything into: best_sequences_from_runs.txt


This ensures that fine-tuning starts only from already optimized candidates.

---

## Model & Embedding Setup

Same embedding pipeline as Stage 1, with two key optimizations:

- **Model precision:** FP16 (half precision) for ESM-2
- **PCA + pooling:** FP32 for numerical stability
- **Layer:** 28
- **Segments:** 24
- **PCA components:** 640

All heavy computations are GPU-accelerated.

---

## Fine-Tuning Hyperparameters

| Parameter | Value |
|------------|--------|
| Steps | 6000 |
| Proposals per step | 32 |
| Initial β | 5000 |
| Final β | 20000 |
| Record threshold | 0.992 |

Selection pressure increases linearly during the run:

\[
\beta(t) = \beta_{start} + (\beta_{max} - \beta_{start}) \cdot \frac{t}{N_{steps}}
\]

This creates a gradual transition from exploration to near-deterministic optimization.

---

## Adaptive Mutation Strategy

Only substitutions are used in this stage (no insertions/deletions).

Mutation temperature adapts to similarity:

| Similarity | Temperature |
|------------|-------------|
| > 0.99 | 0.8 |
| > 0.98 | 1.0 |

Additionally, temperature decreases smoothly over time:

\[
T(t) = 1.5 - progress
\]

This produces:

- Early stage → moderate exploration  
- Late stage → extremely local refinement  

---

## Selection & Acceptance

At each step:

1. Generate `K_PROPOSALS = 32` mutated candidates.
2. Compute embeddings in batch.
3. Select the best candidate in the batch (greedy pre-selection).
4. Apply Metropolis acceptance:

If:
\[
\Delta > 0
\]
→ always accept.

Else:
\[
P = e^{\beta \Delta}
\]

Because β becomes very large near the end, the process becomes effectively greedy.

## Analysis

The analysis pipeline is designed to evaluate the biophysical constraints learned by the ESM-2 model by processing the generated MCMC trajectories. The pipeline is fully automated and divided into four main steps:

### 1. Data Extraction & Filtering (`Step 1`)
- Parses the raw output generated by the MCMC sampling.
- Filters the generated sequences based on a strict **Cosine Similarity threshold** compared to the Wild-Type (WT) representation (e.g., `> 0.97` for Generation 1, and `> 0.99` for highly optimized Generation 2).
- Randomly samples a fixed number of valid sequences from each independent run to ensure statistical balance.

### 2. Intra-Run Alignment (`Step 2`)
- Performs a Multiple Sequence Alignment (MSA) on the sampled sequences within each independent trajectory.
- Utilizes **FAMSA**, a highly scalable and accurate algorithm designed for large-scale protein alignments.

### 3. Local Trajectory Analysis (`Step 3`)
- Analyzes the mutational landscape of each independent run.
- Computes key positional metrics, including the dominant amino acid frequency, average conservation score, and Shannon entropy.
- Automatically generates mutational **Heatmaps** to visualize sequence exploration within individual trajectories.

### 4. Global Consensus & Topo-Mapping (`Step 4`)
- Extracts a single, gap-robust consensus sequence from each intra-run alignment using a strict majority-vote algorithm.
- Performs a **Meta-MSA** (Global Super-Alignment) combining all run-consensus sequences alongside the exact WT target.
- **Topological Mapping:** Crucially, the pipeline maps the super-alignment strictly back to the native WT coordinates. Unmappable insertions generated by ESM-2 are discarded, preserving the true topological numbering.
- Computes final inter-trajectory metrics: **Global Support (%)** for consensus mutations and **Global Positional Entropy**.
- Generates the final publication-ready plots: *Mutation Landscape* and *Structural Flexibility Profile*.

To execute the analysis, run the `msa_pipeline.py` script from your terminal. The script is highly modular and requires you to specify the operational mode, with the option to select specific steps of the pipeline.

### Basic Command
```bash
python3 msa_pipeline.py --mode <MODE> --step <STEP>
```

##  Biochemical Feature Analysis

To complement the embedding-based pipeline, this repository includes a standalone analysis for the biochemical characterization of the generated sequences compared to the Wild-Type (WT). This module bridges the gap between the LLM's latent space and actual protein biophysics.

### 1. Global Physicochemical Properties
We utilize **Biopython** (`ProteinAnalysis`) to compute macroscopic sequence descriptors, ensuring that the generated variants remain within a realistic physicochemical regime relative to the native targets. Key metrics extracted include:
- **Isoelectric Point (pI):** The pH at which the protein carries a net zero charge.
- **Instability Index:** Predicts *in vivo* stability (values < 40 indicate a stable protein).
- **GRAVY Score:** Evaluates the overall hydrophobic or hydrophilic character of the sequence.

### 2. Local Sliding-Window Profiles
To capture position-dependent effects and contextualize structural deviations, we compute smoothed biophysical profiles using a sliding window approach (*w* = 9). These profiles are overlaid across the native structural regions (e.g., TM anchor, proline-rich linker) and include:
- **Hydrophobicity** (Kyte–Doolittle scale).
- **Backbone Flexibility** (Vihinen scale).
- **Net Charge per residue**.

### 3. Embedding–Feature Space Relationship
Beyond descriptive statistics, we explore the correlation between representation-level similarity and classical biochemical descriptors. Using **[iFeatureOmega](https://github.com/Superzchen/iFeatureOmega-CLI)**, we extract comprehensive biochemical feature vectors for each sequence. By comparing the distance in the embedding space  with the distance in this feature space, we demonstrate that the model's learned representation intrinsically encodes coarse-grained physicochemical constraints.

**2. Embedding–Feature Space Relationship (Step 3)** `Use the distance_correlations.py` script located in `feature_analysis` directory
